# Test cases

Written from the flows in `unpacked/Workflows/`, the app sources in `apps_src/`, and the proposed flows in [new-flows-design.md](new-flows-design.md). **Nothing here has been executed.** Expected results are what the files say should happen.

**Tags in the Scenario column:** **[EXISTING]** = behaviour of the current solution. **[NEW]** = needs one of the flows from the design doc. **[KNOWN DEFECT]** = the current solution is expected to give the wrong result; the expected result shown is the *correct* behaviour, so the test should fail today.

## Test set-up

- A dev environment with the solution imported, the `default` Leave Manager Setting row present, and `contoso_sendmeetingrequest` = Yes.
- Four test users: **Employee**, **Manager** (the employee's Office 365 manager), **HR approver** (uses the HR Approve app), **HR capturer** (uses the HR Capture app). Each has a mailbox.
- The holidays from `data/indian-holidays-2026.csv` imported. Leave type with a balance row for the employee.
- "Run history" means the flow's Run history in Power Automate. "History table" means `contoso_leaverequesthistories`.
- **Ageing a request for escalation tests:** edit `contoso_lastactortimestamp` on the row directly (table grid or API) to now minus 3 days / now minus 5 days. Editing that column also triggers `Create History Record`, which is expected.
